## Fix order

Ordering principle: irreversible loss first, then unrecoverable state, then false assertions about credentials/recording/money (the things AGENTS.md makes load-bearing), then false success, then a broken documented contract.

**1. Worktree "unreadable" collapses to "none", and force-delete is built from it** — `src/main/worktrees.ts:466-467`
```ts
dirty: dirty.count ?? 0,
ahead: ahead.count ?? 0,
```
`WorktreeInfo` (`src/shared/types.ts:1126-1127`) declares both as `number`, so the `Dirty`/`Ahead` shape main carries specifically to preserve "git could not say" — with its own comment at `worktrees.ts:160-167` explaining that collapsing it to 0 is what the refusals exist to prevent — is thrown away at the IPC boundary. `Settings.tsx:4781-4787` prints `none`; `4794-4796` builds the confirmation from the same collapsed values; `yes, delete` calls `remove(w, true)`, and force bypasses the `dirty.count === null && !force` refusal at `worktrees.ts:670`. Only this finding destroys work that exists nowhere else. Note: the secondary scenario (`ahead === 0`, both columns null→"none", no confirmation) is milder than claimed — it calls `remove(w, false)`, which lands on main's refusal. The display is still wrong; the loss path is the `ahead > 0` one.
