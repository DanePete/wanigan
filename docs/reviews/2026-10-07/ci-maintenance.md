# CI fixture maintenance race

Commit: `e21d97ad8bc181aeab63ca707f196c42b0c56475`.

`src/core/session-life.test.ts:140` initialized and committed its temporary repository immediately before taking the “writes nothing into its folder” baseline. Git 2.55 could leave its automatic maintenance child running after that setup commit returned. GitHub run `37692272337` captured an empty `.git/objects/maintenance.lock` in the baseline; the later snapshot differed only because Git had removed that transient lock. The other 521 unit tests passed.

This is consistent with Git's implementation: `prepare_auto_maintenance` invokes `maintenance run --auto --detach`; the maintenance runner takes the object-store lock, detaches, runs its background tasks and rolls the lock back. See [Git 2.55 run-command.c](https://github.com/git/git/blob/v2.55.0/run-command.c#L1850) and [the maintenance runner](https://github.com/git/git/blob/v2.55.0/builtin/gc.c#L1670). [Git's configuration reference](https://git-scm.com/docs/git-config#Documentation/git-config.txt-maintenanceauto) documents disabling automatic maintenance.

The fixture now sets `maintenance.auto=false` through environment configuration only in its setup child shell. It does not change the production git runner, user/global configuration, or repository configuration. The existing folder snapshot and final clean-status assertion are unchanged. The snapshot includes `.git` file contents except its pre-existing `.git/index` exclusion; checkpoint tests separately compare index bytes. This correction adds no exclusions. No lock filename was excluded and no sleep/retry was added.

A permanent Trace2 assertion records setup outside the project and requires that it start no maintenance child. With the original setup and the locally built Git 2.55.0, this assertion failed deterministically: `child_start` named `git maintenance run --auto --quiet --detach`. After the fix, all five `session-life.test.ts` tests passed with Git 2.55 fixture setup and with the system Git 2.50.1, along with fresh type checking and `git diff --check`.

Evidence kept during review: `maintenance-red.log`, `maintenance-git255-green.log`, `maintenance-system-git-green.log` and the independently fetched `maintenance-ci-failed.log` under `/private/tmp/wanigan2-review/`. Additional full-unit validation passed 523/523 with Git 2.55 fixture setup and the core’s system Git 2.50.1. The first run failed three fixture creations because this locally built Git had no installed templates; supplying its built standard templates through `GIT_TEMPLATE_DIR` resolved those environment errors without source changes. Both logs are retained as `alpha3-git255-unit-no-templates.log` and `alpha3-git255-unit.log`. This is not full core Git 2.55 parity; the actual GitHub runner supplies that environment.
