## Confirmed discovery bound mismatch

`src/core/history.ts:242–255` enumerates all matching Claude files and populates `summaries`; `:306–312` uses SQL `.all()` without a row limit for Codex user threads. `:142–147` slices only after discovery, mapping, filtering and sorting. The summaries cache also has no eviction. The bounded per-file head/tail reads do not bound total scan work.

Reproduction: `/private/tmp/wanigan2-review/standards-batch6-zv9_lzgg/history-scan-proof.ts` creates 600 tiny unique Claude JSONL fixtures under the `testCore()` fake home, asks for limit 1, and observes `{"requestedLimit":1,"returned":1,"summariesReadAndRetained":600}`. The process exits successfully and removes its disposable store. This is a confirmed resource-growth issue and a false “scan is bounded” statement at `docs/features.md:238` and README’s History row. A proper fix needs limits on enumeration, imported Codex rows, work/caches, and an honest truncation indication; reducing the returned result limit alone will not fix it.

## Still-green proof gaps worth adding tests for

1. Distinct staged and unstaged tracked edits for commit and commit-message drafting; assert exact committed tree and absence of unstaged sentinel from model input.
2. Secret-scan truncation crossing both 200 commits and 16 MiB; prove missing/stale acknowledgement refuses before any publication.
3. Invoke actual undo for pruned snapshots and preexisting ignored files, then compare bytes/index/checkpoint rows.
4. Jev held-response edits to title/body/type/priority/criterion text, a >5-candidate payload, and refused-key behavior with waiting queue entries.
5. Oversized skill text, alternate account naming forms, and native updater/awake wiring where unit fakes currently stop.

These are proof limitations, not automatically additional runtime defects. The confirmed History resource issue and incorrect Developer-ID explanation are distinct findings.
