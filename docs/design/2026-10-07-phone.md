# Wanigan on your phone

7 October 2026. Decided with the owner in conversation.

## What it is for

Being away from the desk and still running the desk: see what needs you and
answer it, work in a session (read it, type into it, send it a message, stop
it), and start a new one, on a card or not. Usable by anyone who can install an
app, without a Wanigan account or a Wanigan server.

## How the phone reaches the Mac

Through **Tailscale**, made one click. The owner installs the free Tailscale app
on the Mac and the phone and signs both in to the same account. In Settings ›
Phone, Wanigan:

1. Says whether Tailscale is installed, running and allows HTTPS, with Tailscale's
   own links when it is not.
2. On **Set up phone access**, shows and then runs
   `tailscale serve --bg --https=443 --set-path=/wanigan http://127.0.0.1:47832`:
   a private HTTPS address on the owner's own tailnet, mounted under `/wanigan`
   so nothing else they serve is touched. Wanigan itself listens on loopback
   only; it is never a server on the Wi-Fi the Mac joins.
3. Shows a QR code: the address, with a single-use pairing code (10 minutes) in
   the fragment, which never reaches a server log. The phone opens it, pairs, and
   is walked through Add to Home Screen and notifications.
4. Lists paired phones, each with what it may do and Forget; **Turn off** removes
   the Tailscale address and stops listening.

## What a phone may do

A paired phone is a third kind of caller in the core, beside the window and the
agents, with its own list of methods:

- **Read:** projects, Needs you, sessions, a session's terminal, boards and cards,
  accounts with what each plan has left, models.
- **Act** (each phone, chosen when it is paired, on by default): answer a
  permission, reply, type into a terminal, stop a session, start a session (on a
  card or not, any agent, account and model), create a card, accept or archive
  one, approve or send back one in review.
- **Never:** settings, accounts, git, skills, MCP, files on the Mac, Jev's key,
  pairing other phones.

Everything a phone does is recorded in Activity as done from that phone.

## How it is built

- **Core:** `src/core/phone/` — devices (pairing codes, hashed tokens, what
  each may do), the gateway (an HTTP listener on 127.0.0.1 that serves the phone
  page and takes requests and an event stream, authenticated per device), the
  Tailscale wiring, and Web Push (VAPID, RFC 8291 encryption).
- **Page:** a second, lighter entry in the renderer (`phone.html`), its own small
  screens reusing the shared parts (the API client, the terminal, the selects,
  the limits bars), at phone width, in both themes. Installable: a manifest and
  a service worker that only shows notifications.
- **Window:** Settings › Phone.

## How it is proven

Unit tests for pairing (single use, expiry, brute-force limit), each phone method
allowed or refused, a phone that may only read, the gateway's authentication and
event stream, the Tailscale commands (against a stand-in `tailscale`), and the
push encryption against RFC 8291's own test vector. Phone-width screenshots of
every screen in both themes. A real run through the owner's Tailscale address on
this Mac. A notification on a real phone needs the owner's phone.
