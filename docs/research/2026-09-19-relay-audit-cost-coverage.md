# Relay audit: cost, recovery and coverage for the next session

Read-only source audit on 2026-09-19 at `324bca7f137198a78583ec9b8cb07cfd1c667c71`. No test suite, provider connection or paid call was run for this note. The user authorized **$50 total API spend for the next session, including JEV, retries and review**. This is an experiment-wide allowance, not $50 per goal. Root owns the integrated execution plan.

## Confirmed facts and limits

- The shared spending predicate allows known zero before any launch and explicitly reported zero, but refuses missing/partial dollars, invalid amounts, absent budgets and reached budgets. Control checks it at sweep, dequeue and immediately before spawning after asynchronous preparation. This stops another automatic action; it cannot cap a turn already running. [Predicate][spend], [Control dispatch][dispatch], [operator contract][contract].
- Spending uses the union of current and prior task sessions, so reopening does not erase an attempt. Frozen review evidence preserves failed attempts, cached tokens, unknown buckets and mixed routes; a node with no launched session receives no model credit. Review snapshots are cumulative: **do not sum the rejected $7 snapshot and later accepted $9 snapshot as $16**. [Spend population][population], [outcome writer][outcomes], [actual SQLite fixture][outcome-test].
- Codex native counters do not establish dollar cost. Frozen attempt deltas require usable interval evidence and no recorded overlap; otherwise conversation totals remain separately labeled. The live session display can still show cumulative thread counters. Neither display totals nor cached input multiplied by a public list price are invoice evidence. [Codex readers][codex], [delta rules][tokens], [prior live trial][trials].
- The three earlier live tasks used real Codex and edited real worktrees, but were not a controlled quality/cost comparison. Their Codex dollars were unreported, and no final human approval was fabricated. That run predates this automation implementation; it is not proof that the complete new unattended path works. [Trial provenance][trials], [current implementation verification][contract].
- JEV receipts are main-owned, single-use and bound to input/profile/credential/policy context; unchanged creation reuses a preview. JEV dollar figures are estimates recorded separately from agent cost. Transport failures/timeouts and non-success HTTP responses return before the successful-call usage write: billing after an ambiguous failure cannot be inferred as zero from the local ledger. [Receipt implementation][receipts], [JEV transport][suggest].
- The forecast is not an accepted-result predictor: it selects completed phases, totals all recorded attempts, then labels the sample with the node's current provider/model/effort. Mixed-route retry cost must not be used to rank the final model as though it did all the work. Use frozen attempt/outcome evidence for experimental analysis. [Forecast query][forecast], [outcome writer][outcomes].
- Generic or missing profiles cannot receive automatic paid dispatch. OpenRouter's experimental CLI connection remains manual and unverified for billed cost; a public catalogue or successful generic launch does not upgrade that support. [Dispatch eligibility][dispatch], [connection contract][openrouter].

## Experiment ledger and stop rule

Use one append-only experiment ledger across all goals. Before each external request or session, assign a case/attempt ID and record approved maximum exposure, route/profile/backend/account identifier, model/effort, commit, meter provenance and remaining allowance. Record JEV, implementation, repair and any model review separately, then reconcile provider-reported/billed cost without also counting estimates as extra invoices. Store only sanitized operational evidence and paths to local artifacts, not credentials or raw private prompts.

The product's per-goal guard excludes JEV and is not this ledger. Reserve room inside the **$50 aggregate** for retries, ambiguous requests and final reconciliation; do not spend the entire nominal remainder based on lagging telemetry. Unknown expense is unresolved exposure, not $0. If a CLI cannot establish dollar exposure, use the offline case or stop that live route; do not bypass its guard or convert subscription quota into invented API dollars. A ledger and turn limit cannot guarantee a provider-enforced hard cap: verify a compatible billing control before promising that guarantee. Stop paid work when exposure cannot be bounded within the remaining approved total.
