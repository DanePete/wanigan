# Sessions composer layout — research, 11 September 2026

The composer region under the terminal stacks six rows of chrome around one
textarea. This is the research behind shrinking it: 8 grounding agents (3
measuring the real files, 2 on external precedent), 4 independent proposals from
deliberately different starting principles, 3 critics each (honesty /
accessibility / style-gate feasibility), then a synthesis that re-measured the
winner rather than repeating its numbers.

22 agents, 0 errors, 114 grounded notes.

## Proposals as scored

|---|---|---|---|---|---|

## Critiques

### One Box, One Line

- **ok 7/10** — Most dispositions survive this lens, and two of them are honesty *improvements*, not trades. Row 3 is a clean "show only when it differs from the default": the four strings it flattened all map to longer, state-specific sentences in shared/composer-queue.ts:26-43, and critically the unknown state (attention===null, Composer.tsx:266) still speaks — so silence means verified-idle and never means unread, which is the precondition the dark-cockpit convention actually requires. Row 6 ends up better placed (adjacent to the control, aria-describedby instead of a hover-only title=), and splitting flash from reason fixes a standing 3.5s lie. Row 5's state-derived verb retires a hint that is currently false with the skill menu open (Composer.tsx:401) and in blocked mode (:359). Row 1's "Name again" loss is a non-loss: it is disabled whenever items.length === 0 (Sessions.tsx:2211), i.e. in exactly the state where the band now disappears.

Two holes, both landing precisely where honesty is load-bearing.

(1) BLOCKING AS WRITTEN — the loading state. The proposal's invariant is "absence can never mean unknown, because loading renders nothing at all." That reasoning is inverted: rendering nothing during an unread state is exactly how absence comes to mean unknown. phase is re-set to 'loading' on every session switch (Sessions.tsx:2009) and the band currently says so twice ("reading…" and Sessions.tsx:2228 "Reading what is staged for this session…"). Delete the band during loading and, by the proposal's own trained convention, the region asserts "the read finished and found nothing" for a window whose length is an IPC round-trip the renderer does not control — for a session with three files staged, it asserts a false negative. That is the guess-as-observed-fact AGENTS.md forbids, and it is the one place where a fact on screen today ("reading…") has no named destination. It is not fatal only because the proposal already built the channel that fixes it at 0px.

(2) The reason truncates, and the fallback copy is deleted in the same commit. Row 6's disposition is sound, but the mechanism specified for row 5 will not degrade the way it claims. A flex item with min-width: 0 shrinks to zero before flex-wrap: wrap ever fires, so the status slot ellipsises long before the row wraps, while the six flex:none buttons keep their width. At a ~560px composer the longest reason — "The agent is waiting on a permission prompt — queued text must not answer it." (77 chars, the most safety-critical of the five) — truncates mid-clause. And because the same change deletes the Send button's title={state.reason} (Composer.tsx:538), the truncated line is then the *only* sighted copy. The proposal lists truncation as cost #5 and accepts it; under this lens a reason the operator cannot finish reading is hidden state, not compressed state.

Smaller, still worth fixing: (a) the sent-file counter — "the only record anywhere that files were sent" — moves into a .statusbar (index.css:864-871) with no overflow:hidden, no min-width:0 on the path span (Sessions.tsx:1136), and a project path that cannot shrink below min-content; adding an item there silently clips whatever ends up rightmost. (b) The proposal over-claims the drop overlay "already carries two of" the Explainer's three sentences. Sessions.tsx:1062-1063 carries roughly one, partially: it has "staged where this agent can read them" but not "writes the path into your prompt", not "paste a screenshot with ⌘V" (which exists nowhere else in the UI — grep finds no paste entry in bindings.ts), and not "Sent files leave this strip" (Sessions.tsx:2237) — the sentence the redesign makes *more* necessary, since after it the strip is absent at rest and a chip vanishing has no explanation on screen. (c) aria-describedby="composer-status" pointed at a multi-tenant element makes the stash flash, attach notice and character countdown part of the Send button's accessible description.

'Reading what is staged…'` as the lowest-priority occupant, below reason and above the key hint — and keep the band's render condition as proposed. Absence then means "read completed, nothing staged" in every case, the invariant the proposal needs is actually true, the duplicate loading line at Sessions.tsx:2228 still dies, and the height stays constant so the session-switch PTY resize is still removed. Cost: 0px.

If a floor is refused, then keep `title={state.reason}` on Send rather than deleting it, because a truncated sentence plus no tooltip is strictly less than today.

- **ok 7/10** — On the composer half (rows 3-6) this is honesty-POSITIVE, and I want to say that first because it is the part most likely to be argued about. Deleting row 3 removes a duplicate and two actual defects: `deriveSendState` (src/shared/composer-queue.ts:36-42) returns four distinct queue reasons that row 3 flattens into one "Queues until idle", and in the attention===null state row 3 asserts queueing behaviour no read has established while the reason string honestly says "not known yet". Deriving the ↵ verb from mode fixes a hint that is false in two states today.

The gaps are all on the attachments half, and they are the same shape as the defect the proposal congratulates itself for fixing.

1. BLOCKING — the loading state's only statement is deleted, and absence then asserts a fact no read established. `useEffect(() => { setPhase('loading'); void load(); }, [load])` (Sessions.tsx:2009) re-enters loading on every session switch, and `load()` never clears `items` — setItems fires only after the await (:1988). `useAttachments` is one un-keyed hook instance (:633). So on a switch the previous session's chips are still in state while the read is in flight. The proposal deletes both copies of the loading text ("reading…" at :2197 and "Reading what is staged for this session…" at :2228) and drops the zero case on the argument that "an absent shelf already says it". That argument fails precisely here: a shelf built on `items.length > 0` will show the OLD session's files, or be absent and imply "nothing staged", before anything has been read. The cascade has a tenant for `phase === 'error'` and none for `phase === 'loading'`, which is the one state where the dark-cockpit precondition (absence is a reliable signal) does not hold.

2. BLOCKING — the error Note's content has no destination that can hold it. The proposal gives error "its own status tenant ('Could not read what is staged')" in a single reserved line with `min-height: calc(var(--t-micro) * 1.45)`. The existing Note (Sessions.tsx:2219-2226) carries three things that line cannot: the verbatim `att.loadErr`, the reassurance that staged files are still on disk in the session's attachment folder, and a **Retry** button. A 16px one-tenant line replaces a Note plus a control. That is information and an affordance simply gone, and the proposal's own measurement (the longest reason needs 414px against a 460px dock) proves the line has no room for error text appended to it.

3. The strict one-tenant cascade makes facts that are co-visible today mutually exclusive. `.composer-note` renders the reason AND the character countdown in the same element (Composer.tsx:545-553), and the chord hint sits beside them in the action bar — three things on screen at once. Collapsing all of it into one slot means the countdown displaces the reason (a long mid-turn draft loses "The agent is mid-turn; this sends when it goes idle.") and ⇧↵ / $ vanish for the entire mid-turn period — the window in which an operator is most likely to be drafting a multi-line follow-up. The grounding's own note that row 5's slot is "already conditional by width" licenses width-keyed suppression, not state-keyed suppression by a competing tenant.

4. `role="status"` wrapping the countdown is a new defect. role=status is polite and implicitly atomic, so a countdown that changes per keystroke re-announces the whole line — reason included — on every character. Today nothing announces; the fix for a sighted-only reason should not ship a screen-reader flood.

5. The overlay's occlusion is declared, but the one case it must not cover is unhandled. Everything the cost section defends is operator-caused (typing, staging, queueing) and therefore an expected shift. A permission prompt is not: the agent renders it in the terminal's bottom rows, which is exactly what the shelf and the expanded sheet paint over, and "queued text must not answer it" means the operator has to read the terminal to act. A never-covered status line saying a prompt exists is not the same as being able to see it.

6. "Name again"'s purpose has no on-screen home. Its title= (Sessions.tsx:2213-2216) carries two facts, not one: the exited-session reason (covered, it is the blocked reason) and "Attaching already names these files in your prompt. Use this to name them again — after clearing the input, say." That second sentence exists nowhere else, and both files are at their title= ceiling (Composer 8/8, Sessions 30/30), so it has to become visible text or the control becomes unexplained.

The "after one attach the strip sits at 102.39px indefinitely → −128px ≈ 7.8 rows" ledger line rests on a fact the code contradicts, and the grounding note it came from is wrong. The at-rest (−91px) and mid-turn (−113px) figures stand.

## The final shape

`.composer.composer-workspace` (padding `--s-2`) → `.composer-row` (the bordered box) → `.composer-field` (untouched) + `.composer-actions`:

```
[＋ Add files] [.composer-status — 2 reserved lines] [⌄] [/compact] [⧉ Saved] [Send|Queue]
```

`.composer-status` is `flex: 1 1 30ch; min-width: 24ch; min-height/max-height: calc(2 * 1.45 * var(--t-micro)); overflow: hidden` with `flex-wrap: wrap` on the row. Measured: **identical height in all seven session states at every width from 560 to 1400, in both pointer modes, with zero truncation of any reason string.** That is the headline — the composer's height stops varying with agent state, so the agent's own state stops firing `proc.resize` at a live PTY twice per turn.

**The cascade, one occupant, highest first** (and I measured why it must be exclusive: with both the reason and the chord hint rendered, the 77-char permission reason clips at 680px and below — `CUT h16/32`):

1. `over > 0` → `N over the 100,000-character limit`, tone critical
2. `attachPhase === 'error'` → `Could not read what is staged — see the list below`, critical
3. `state.reason` → the verbatim sentence, warn for `queue` / critical for `blocked`
4. `attachPhase === 'loading'` → `Reading what is staged…`, quiet
5. `flash` → the ⌘S confirmation, quiet
6. otherwise → `↵ <verb>  ⇧↵ new line  $ skill` with the verb derived from state

Plus two `flex: none` siblings that can never displace the above: the character countdown (both branches) and the attach meta (`N staged · N sent · N visual tokens ≈ $X`, only when `sent > 0 || visual > 0`).
