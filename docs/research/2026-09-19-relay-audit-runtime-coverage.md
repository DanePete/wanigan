## Highest-risk integration gaps

1. **Checkpoint availability and first-write ordering need direct proof.** In [sessions.ts](../../src/main/sessions.ts), `pty.spawn` is at line 1618; checkpoint registration is later at line 1728. [registerSessionCheckpoints](../../src/main/checkpoints.ts) starts an asynchronous capture without a launch barrier. Thus the comment promising a snapshot before the agent's first action is stronger than the ordering proves. Also `hooksCapable: injected.includes('--settings')` follows the Claude settings path, whereas Codex hook arguments are prepared separately. Current code therefore does not establish equivalent Codex checkpoint capture. [SessionReview](../../src/renderer/src/components/SessionReview.tsx) advertises support from `session.capabilities.hooks`, which needs comparison with actual rows. These are source-derived concerns, not newly reproduced failures.
2. **A recovered database row does not prove the old process stopped.** [review.ts: runCommand](../../src/main/review.ts) starts detached command groups and kills them on timeout. [index.ts: before-quit / stopServices](../../src/main/index.ts) stops services and awaits session/headless shutdown, with no review-command shutdown handle visible. `sweepInterruptedRuns` marks old rows failed and says the commands stopped with Wanigan. Test actual descendant PIDs and continuing writes on quit/crash before relying on that statement.
3. **Restore preview is not a durable authorization for an unchanged file set.** [checkpointRevertPlan / applyCheckpointRevert](../../src/main/checkpoints.ts) independently capture and compute actions; apply takes a fresh safety snapshot, but accepts no preview fingerprint and the preconditions do not reject a live writer. The [CodePanel restore flow](../../src/renderer/src/components/CodePanel.tsx) sends only the checkpoint id. Exercise preview-to-apply changes and concurrent writes. A safety snapshot improves recoverability; it does not itself establish that the operator reviewed newly affected paths.
4. **Isolation and freshness have deliberate limits.** [private dependency preparation](../../src/main/worktrees.ts) requires same-volume APFS cloning and refuses external links/hardlinks or a scan exceeding 500,000 entries/30 seconds. [review-checkout.ts](../../src/main/review-checkout.ts) limits fingerprints to 20,000 files, 1 GiB total, 16 MiB per file and 15 seconds; ignored inputs, tool versions and external state are outside its claim. Trials should verify honest refusal and responsive UI, not assume all repositories/dependency layouts are supported.
5. **Install success needs artifact and UI evidence.** [launchAndVerifyInstalledWanigan](../../scripts/install-local-macos.cjs) checks the exact bundle process remains running after a stability delay. That is stronger than `open` succeeding, but weaker than a functioning renderer/IPC/PTY. Compare built output with ASAR entries, then packaged and installed ASAR/unpacked native bytes; version `0.1.0` alone is not a commit identity. In [dist:mac:arm64](../../package.json), the shell preserves the builder exit status after `npm run rebuild`; inspect the rebuild result separately because its failure can be masked by a successful builder.

## Twelve adversarial scenarios and pass criteria

All destructive, restart, filesystem-race and malformed-state cases use a **disposable clone, independent dependency tree, isolated userData, and fixture accounts/configuration**. Do not link its `node_modules` to this checkout. Destructive installation cases additionally require a disposable application destination or test macOS account/VM. Never use the operator's live sessions as the failure fixture. Criteria below are proposed acceptance conditions; a currently failing condition becomes a finding, not a reason to relabel the result.

| # | Scenario and execution seam | Required observation / pass criterion |
| --- | --- | --- |
| 1 | **First prompt and resume grammar.** Exercise `createSession`, `recoverExactCodexThread` and real `TerminalPane`; new launch, exact UUID resume and picker-only resume. Include multiline text, literal `$&`, leading dashes and a startup update/trust modal. Start with a credential-free executable fixture; then one small Relay task on each funded, supported harness. | The intended prompt reaches the chosen conversation exactly once and is not a session selector or shell command. No delayed duplicate paste after argv delivery. Record executable/version, argv with secrets redacted, actual cwd and conversation id; no automatic Enter into the modal. |
| 2 | **Current readiness and renderer reattachment.** Extend `submitInitialCodexPrompt`, shared `codex-prompt` and terminal-replay coverage with fragmented redraws, stale ready markers, a modal appearing between paste/Enter, manual typing, switching tabs and replayed cursor/device queries. | Unknown/currently blocked output receives no Enter; typing cancels pending auto-input. Reattaching renders history without sending it or terminal query replies back to the actual PTY. Later deliberate input still works. |
| 3 | **Real failure hand-back.** Through Relay, run an operator-approved verifier that fails once, then passes after the intended fix. Include multiline/ANSI-looking failure output, duplicate Stop delivery and a late approval modal. Exercise `goal-gate` plus `sessions.writeSession`. | One eligible failure yields one bounded feedback attempt and one actual submitted turn; bracketed paste alone creates no synthetic new turn. Duplicate/late events cause no second retry or modal Enter. Failure text remains data; deterministic verification itself starts no model. |
| 4 | **Authorization changes during preparation.** Delay worktree/config preparation and change pause, halt, task ownership, route/profile availability, cap or meter coverage. Exercise Control's final guard and `createSession`'s `beforeSpawn`. | No PTY/backend request after refusal; the queue claim resolves coherently, prepared state is explained and an adopted checkout remains intact. Ordinary free verification can still run when paid dispatch is blocked. No money is needed for the race fixture. |
| 5 | **Package-manager isolation.** In a disposable Relay implementation tree, run a harmless local package install/removal fixture. Separately inject clone failure, insufficient space, root/nested external symlinks, hardlinks and unsupported volume/layout. Exercise `placePrivateDependencies`, retry adoption and relink. | Parent dependency sentinels/hashes remain unchanged; no shared fallback, agent spawn or setup follows failed private preparation. | 7 | **Quit/crash during work.** Separately quit and kill the isolated app while a fixture CLI writes and while a detached review descendant writes a sentinel. | 8 | **Actual checkpoint boundaries and instant first edit.** Launch a fixture that edits immediately, with pre-existing dirty contents. Then observe actual supported native hooks on the smallest funded Relay task. Exercise registration, UserPromptSubmit/Stop and exit finalization. | When checkpoints are advertised, the launch snapshot contains the pre-agent bytes and turn/end rows match actual boundaries without touching the user's index/HEAD. Failed/unsupported capture is explicit. Current Codex absence must be reported honestly; do not substitute forced `hooksCapable: true` as conformance evidence. |
| 9 | **Restore race and undo.** Preview a checkpoint restore, create/change another file, keep a writer active, change a path to a symlink, remove the checkout and force safety-capture failure in separate fixtures. This probes the known preview-binding gap. |
| 10 | **Fresh verification versus stale/unsupported evidence.** Run real commands, then mutate same-size/restored-mtime contents, staging/HEAD, recipe, ignored dependency input and large-file limits; start a newer failing run. Exercise `runAt`, freshness and approval. | Only the latest relevant, matching checkout/recipe evidence can authorize completion. ## Run order and evidence

Next session: establish commit and isolation → `npm test` plus terminal replay probe → free real-PTY/hook/process/filesystem integration fixtures → fix blocking safety failures → only then the bounded Relay coding and retry trials → package/reopen verification. Real API work is unnecessary for most adversarial cases. A budget or telemetry uncertainty stops additional paid launches; it does not require buying more evidence to explain the uncertainty.

Keep a compact per-scenario record: commit and build hash; fixture versus real-run label; timestamps and exact entrypoint; node/session/review/checkpoint ids; canonical checkout and Git/index/content identities; process/descendant observations; sanitized provider/profile/backend/model/effort attribution; expected result, observed result and artifact paths. Paid records also link actual usage/spend and retries into the shared $50 ledger. Screenshots establish visible state only. Report failures and unavailable evidence alongside passes; do not turn fixture coverage into a production reliability or savings claim.
